# UI スタイルガイド（色・タイポ・余白・部品）

作成日時: 2026-08-11 17:59
更新日時: 2026-08-11 17:59

本アプリの UI を設計・変更するときの唯一の指針。アートスタイルを一貫させるための規則をここに集約する。
トークンの実体は `src/styles.css` 冒頭の `:root` / `[data-theme='dark']` ブロック。共通部品のセレクタ群は同ファイルの「共通コンポーネント」節。

> このファイルは旧 `docs/design/design-guidelines.md` を置き換えたもの（内容を引き継ぎ、§4「余白」を追加）。

## 0. 適用ルール（必読）

**UI に関わる変更を行うときは、毎回このスタイルガイドを守る。** 対象は、見た目・レイアウト・配色・文字・余白・アニメーションに影響するすべての変更（新規コンポーネント、既存画面の調整、`src/styles.css` や `.tsx` 内のスタイル指定、小さな一箇所の修正も含む）。

守る手順は次の 3 つ。

1. **着手前に読む。** UI を触る作業では、実装を書き始める前に本ファイル（少なくとも該当する節）を確認する。
2. **既存の段階から選ぶ。** 色・文字サイズ・角丸・余白・影・アニメーション時間は、本ガイドで定義済みの値だけを使う。新しい値や新種の部品を思いつきで足さない。既存の 5 系統のボタン・パネル・モーダル・メニュー等に当てはめられないか先に検討する。
3. **外れるなら、先にここを直す。** どうしてもガイドから外れる必要がある場合は、**実装より先に本ファイルを更新して新しい規則として明文化し**（更新日時も更新する）、そのうえで実装する。ガイドに書かれていない独自スタイルをコードだけに残さない。

作業を終える前に §8 のチェックリストを通す。ガイドに反する既存コードを見つけた場合は、その場で直すか、直さないなら理由を作業報告に書く。

## 1. 基本方針 — 「静かなクローム」

アートスタイルの芯は 4 つ。判断に迷ったらここへ戻る。

1. **本文（紙）が主役**。周辺 UI（バー・サイドバー・ツールバー・パレット）は小さく・淡く・枠線なしを基本にする。
2. **領域は枠線ではなく面の差で区切る**。紙 = `--surface`、クローム = `--bg`。枠線（`--border`）を使うのは入力欄・パネル・モーダルの輪郭だけ。
3. **装飾は追加しない**。色・影・動き・角丸・文字サイズは、このガイドで定義された段階だけを使う。「目立たせたいから」で新しい値を持ち込まない。
4. **参照デザインは Obsidian**（配色・スクロールバー・リサイズ・Vault スイッチャー等）。迷ったら Obsidian の挙動に寄せる。

## 2. 色

**ダークテーマが基準**。配色は Obsidian のデフォルトダークに寄せる（紙 `#1e1e1e` / クローム `#191919` / 文字 `#dadada` / アクセントは紫 `#7f6df2`）。ライトは同じ紫を軸にした従属テーマで、デザイン検討はまずダークで行う。

**色は必ずトークン経由で指定する。HEX 直書き禁止**（例外: 資料種別バッジなどのカテゴリ色）。
ライト/ダークは `[data-theme]` でトークンごと切り替わるため、**コンポーネント側にテーマ分岐を書かない**。

| 役割 | トークン | 用途 |
|---|---|---|
| アクセント（唯一の主張色・紫） | `--accent` / `--accent-text` | 主ボタン、アクティブ状態、フォーカスリング、リンク |
| 選択ハイライト | `--selected` | 選択行・アクティブトグルの背景（ダークではニュートラルなグレー。色では主張しない） |
| 成功・稼働 | `--ok` / `--ok-bg` | モデル稼働ドット、採用済み行 |
| 注意 | `--warn` / `--warn-bg` | 未保存表示、ドラフト復元バナー |
| 危険・削除 | `--danger` / `--danger-bg` | 削除メニュー、エラー面 |
| diff | `--del-bg` / `--del-text` / `--ins-bg` / `--ins-text` | 校正・履歴の削除/追加 |
| 面と文字 | `--bg` `--surface` `--text` `--muted` `--faint` `--border` `--hover` | 上表以外のすべて |
| スクロールバー | `--scrollbar-thumb` / `--scrollbar-thumb-hover` | つまみの色（トラックは透明） |
| 上下バー専用（テーマ非依存ダーク） | `--bar-bg` `--bar-surface` `--bar-hover` `--bar-border` `--bar-text` `--bar-muted` `--bar-faint` `--bar-ok` `--bar-warn` `--bar-danger` | 上部バー・ステータスバー・モデルバー・トースト |
| 上下バー内のアクセント（同上） | `--bar-accent` `--bar-accent-soft` `--bar-accent-border` `--bar-accent-ring` / `-ring-dim` / `-ring-off` / `--bar-accent-glow` | モデルピルのロード済み塗り・枠、ロード中の回転リングとグロー |

### 色の原則

- **アクセントは紫 1 色**。緑・黄・赤は状態の意味（成功 / 注意 / 危険）にのみ使う。
- 文字の階調は `--text` → `--muted`（補足・ラベル）→ `--faint`（disabled・ごく弱い注記）の 3 段階だけ。
- 資料バッジは種別によらず一律の落ち着いたグレー（ライト `#6c727a` / ダーク `#3f454d`）で、種別は M（メモ）/ R（ファイル・リファレンス）/ W（Web）/ A（記事）の文字で示す（色では主張しない）。手動メモ（`source_type='note'`）は編集可能で、本文の正は `manual_note` テーブル、チャンクは `note://<id>` で派生。
- **上下バーはテーマ非依存の常時ダーク**。バー内は `--bar-*` トークンのみを使い、`--bg` / `--text` 等を混ぜない（VS Code 方式）。

## 3. タイポグラフィ・寸法

| トークン | 値 | 用途 |
|---|---|---|
| `--fs-xs` | 11px | ラベル・バッジ・ステータスバー・グリップ |
| `--fs-sm` | 12px | メニュー・パネルヘッダ・補足・バー内 |
| `--fs-ui` | 13px | 標準 UI（ボタン・サイドバー・入力） |
| `--fs-md` | 14px | パネル本文（diff・要約など読ませる文章） |
| `--radius-s` | 4px | アイコンボタン・バッジ・インラインコード |
| `--radius-m` | 6px | ボタン・入力・メニュー項目 |
| `--radius-l` | 10px | パネル・モーダル・カード |

- UI の文字サイズは **px 固定**（em の入れ子で実サイズが揺れるのを防ぐ）。**この 4 段階以外を増やさない。**
- 本文だけが設定値 `--editor-font-size` に追従し、本文内の見出し等は em で相対指定する。
- 太字は意味のあるときだけ（primary ボタン、選択中のメニュー項目、パネルの見出し）。強調のために `--accent` の文字色を乱用しない。
- 数値が並ぶ場所（ステータスバー・スライダー値等）は `font-variant-numeric: tabular-nums`。
- 角丸は 3 段階のみ。**例外はピル型**（候補チップ・トグルスイッチ・モデルピル）で、これは `border-radius: 999px`。
- 影は `--shadow-1`（面の浮き・パネル）と `--shadow-2`（メニュー・モーダル・パレット）の 2 種のみ。影で階層を増やさない。

## 4. 余白

余白トークンは持たない（px 直書き）が、**値は 2px グリッド上の決まった段階から選ぶ**。新しい端数（7px の gap、13px の padding 等）を作らない。

### 4.1 間隔（gap）

| 値 | 用途 |
|---|---|
| 2〜4px | アイコンと文字、バッジの内側、密に並ぶ小要素 |
| **8px** | **既定。** ボタン列・ヘッダ内の操作群・フォーム行の要素間 |
| 10〜12px | 独立したブロック間（メッセージ、リスト項目、設定項目） |
| 16px | 節（セクション）の分離。これより広い余白は使わない |

迷ったら **8px**。`gap` で解決できるものに `margin` を積まない（隣接 margin の相殺と一貫性崩れを避ける）。

### 4.2 内側の余白（padding）

| 部品 | padding |
|---|---|
| ボタン（枠付き ghost / primary） | `3px 12px` |
| バー内 chip・小さいアイコンボタン | `4px 6px` 〜 `6px 8px` |
| メニュー項目 | `6px 10px` 前後（全幅・左寄せ） |
| 入力欄・セレクト | `6px 8px` 〜 `6px 10px` |
| パネル／モーダルのヘッダ | `7px 12px`（コンパクト）〜 `10px 16px`（モーダル） |
| パネル／モーダルの本文 | `12px 16px` 〜 `14px 18px`（読ませる文章は広めの後者） |

**縦は横より狭く**（横 ≒ 縦の 1.5〜2 倍）。これがクロームを薄く見せる要になっているので崩さない。

### 4.3 レイアウトの余白

- 本文・タイトルは中央 **768px カラム**（左右 64px インセット）。本文上のバナー・パネルは **720px** 幅で中央。
- サイドバー・ペイン内のリスト行は**行全体で hover 領域を持つ**ため、行の左右 padding は行側に持たせ、中の文字に margin を付けない。
- 空白で「間」を作りたくなったら、まず**面（`--bg` / `--surface`）の切り替え**で表現できないか検討する。余白を増やすより面を変える方がこのアプリの流儀。

## 5. 部品（コンポーネント規約）

新しい UI 部品は、まず以下のどれかに当てはめる（`styles.css` の「共通コンポーネント」節のセレクタ群に追加する）。当てはまらない新種を作る前に、このファイルに追記して定義を決める。

### ボタン（5 系統）

| 系統 | 見た目 | 使う場所 |
|---|---|---|
| 枠付き ghost（既定） | `--border` 枠 + `--surface` 塗り、hover で `--hover` | パネル・ダイアログ内の操作 |
| primary | `--accent` 塗り + `--accent-text` + 太字（hover は `brightness(1.08)`） | **1 画面（1 パネル）に 1 つまで。** その画面の「主目的」だけ（保存・採用・取り込む・保存してチャンク化 等） |
| メニュー項目 | borderless・全幅・左寄せ。選択中は `--selected` + 太字 | ドロップダウン、サイドバー、設定ナビ |
| アイコンボタン | borderless・`--radius-s`・`--muted` 文字 | 行内の補助操作、閉じる、… |
| バー内 chip | `--bar-surface` 塗り・枠なし | 上下バー内 |

disabled は `--faint` 文字 + `cursor: default`（塗りは変えない）。

### 面もの

- **パネル**（本文上に出るカード: 校正結果・履歴・執筆支援など）: `--border` 枠 + `--radius-l` + `--shadow-1`。ヘッダは 1 行（ラベル `--fs-sm` `--muted`、操作は右寄せ）。本文は `max-height` + 内部スクロール。
- **モーダル**: `--radius-l` + `--shadow-2`、`--overlay` の上。ヘッダ構造はパネルと同じ（例: 設定・資料ビューア・Web 検索・手動資料エディタ `NewSourceEditor`）。
- **ドロップダウンメニュー**: `--surface` + `--border` + `--radius-l` + `--shadow-2`、項目はメニュー項目ボタン。クリック外で閉じる（例: ライブラリメニュー、行の「…」、資料の「＋」追加メニュー）。
- **フローティングパレット**: `ToolPalette` を使う。横長のバー型で、**ビューポートではなく本文ステージに付随**させる（sticky アンカー基準の絶対配置。ペイン開閉でステージが動けば一緒に動く）。`--shadow-2`、グリップでドラッグ移動、位置はステージ相対で localStorage に記憶。z-index は 60。

### 入力・コントロール

- **入力欄**: `--border` 枠 + `--radius-m`、focus で `--accent` 枠。
- **候補チップ**（クリックで即実行する提案。`.chat-suggest-chip`）: ピル型（`border-radius: 999px`）・`--fs-xs`・`--border` 枠 + `--surface` 塗り・文字は `--muted`（hover で `--hover` + `--text`）。**右寄せで縦に積み、固定枠にせず本体（会話）の末尾に置いて一緒にスクロールさせる**（固定するとその高さぶん本体が常に狭くなる）。並びは決まった順に巡回させ、ランダムに入れ替えない（場所を覚えられなくなる）。LLM が生成した項目は `--accent` 枠 + ✨（`SparkleIcon`）で固定項目と区別する。処理中は `disabled`。
- **トグルスイッチ**（真偽値の設定。`.settings-switch`）: 34×18px のピル型トラック + 14px の丸つまみ。OFF は `--border`（hover で `--hover`）、ON は `--accent` 塗りでつまみが右へ 16px スライド（0.12s）。右にラベルを添え、ON / OFF それぞれの意味を短く書く（例「ON（考えてから書く）」「OFF（すぐ書く・既定）」）。`input[type=checkbox]` を視覚的に隠した `<label>` で作り、フォーカスリングはトラックに出す。**3 択以上になるならスイッチではなくラジオ（`.settings-theme-option`）かセレクト**を使う。
- **スライダー**: 細いトラック（4px・角丸）+ 小さめのつまみ（14px・アクセント色）を webkit 疑似要素で自前描画し、左側は `--fill`（つまみ中心の px）までアクセント色。離散ステップは index ↔ 値の配列で対応。**目盛りはつまみ中心の x 座標に絶対配置**（`justify-content: space-between` はつまみ位置とズレるので使わない）。右端に現在値ボックス。
- **既定値に戻す（リセット）UI**: 既定値を持つ設定コントロールには、リセット操作を用意する。インラインの値コントロール（スライダー等）では、**ゴミ箱アイコン（`.settings-reset-btn`）を現在値表示の左に置き**、押すと既定へ戻す。まとまった編集領域（テキストエリア等）では「既定に戻す」テキストボタンでよい（空保存＝既定、も可）。

### z-index の階層

実際に使っている値（`styles.css`）。新しい層を挟むときはこの表に追記する。

| 値 | 層 |
|---|---|
| 10 | 幅可変の仕切り（`.sidebar-resizer` / `.pane-resizer`） |
| 50 | sticky 操作ツールバー（`.editor-toolbars`） |
| 60 | フローティングパレット（`ToolPalette`） |
| 100 | モーダルのオーバーレイ（`.split-review-overlay`。分割ビュー校正・設定・資料ビューア等が共有） |
| 150 | 行内ドロップダウン（`.item-popup` / `.source-add-menu`） |
| 200 | ライブラリメニュー（`.library-menu`） |
| 300 | 画像ライトボックス（`.lightbox-overlay`） |
| 500 | モデル選択モーダル（`.model-modal`） |

- **新しいモーダルは `.split-review-overlay` を再利用する**（独自のオーバーレイと z-index を作らない）。
- 注意: サイドバー系ドロップダウン（150〜200）はモーダルのオーバーレイ（100）より上にある。既存の並びなのでそのままだが、モーダル表示中に出るメニューを新設するときは重なりを確認する。
- トーストは浮かせない。下部ステータスバー左端に出す（`showToast()` → `StatusBar` が `lm-editor:toast` を受けて描画）ので専用の層を持たない。

## 6. レイアウト

- **上部バー**: 3 カラムグリッド `1fr auto 1fr`。左（現在は空き）/ 中央 = モデルピル / 右 = 設定 ⚙️。テーマ非依存のダーク。
- **モデルピル**: 上部中央の状態ボタン（アイコン + 中央テキスト + シェブロン）。クリックでモデル選択モーダルを開く。状態は色で表現（`.model-pill.on/.off/.loading/.error`。story-graph のモデルバーに合わせた） — ロード済み = アクセントの薄塗り + 明るいアクセント枠（`--bar-accent-soft` / `--bar-accent-border`）とアクセント色のアイコン / 未ロード = グレー / ロード中 = 枠が時計まわりに光るリング（conic-gradient を `@property --pill-ring-angle` で回す）+ スピナーアイコン + `読み込み中… <モデル名>` / 失敗 = `--bar-danger` の枠と文字。**塗りつぶしで主張せず、枠とアイコンの色で状態を示す**（バーは静かなクロームのままにする）。
- **下部ステータスバー**: 常時表示。リソースメーターは右端に寄せ、いちばん右に表示/非表示トグル。非表示中もバーとトグルは残す（消すと戻せないため）。テーマ非依存のダーク。
- **エディタ**: 並びは **操作ツールバー（sticky）→ タイトル → 本文**。操作ツールバー（校正・執筆支援・履歴・保存）は全幅・上部固定、書式ツール（太字・見出し・リスト等）はフローティングパレット。本文とタイトルは中央 768px カラム、本文上のバナー・パネルは 720px 幅で中央（§4.3）。本文ステージは `--surface`（紙）のフルブリードでカード枠なし。
- **サイドバー**: `--bg`（クローム）。上から順に、ワークスペースツリー（ドキュメント/資料/画像はフォルダのように開閉、状態は localStorage）→ 下部フッターにライブラリ（= Obsidian の Vault 相当）スイッチャー。幅はドラッグで可変。行の hover/選択ハイライトは行全体（`.item-row`）が持ち、「…」等の操作ボタンもその枠内に入れる。
- **可変幅の境界**（サイドバー・分割ペイン）は当たり判定 6px の仕切りにし、見た目は中央 1px の線を hover / ドラッグ時だけアクセント色でフェード表示（Obsidian 流）。ドラッグ中は幅トランジションを切る。幅は px で localStorage に記憶。
- **スクロールバー**は細い・角丸・トラック透明の Obsidian 風。独自にトラックを塗らない。

## 7. インタラクション

- hover/active の遷移は `0.12s ease`（**背景・文字色のみ**）。それより長い・大きいアニメーションはスライドペイン（0.28s）とトーストだけ。移動・拡大縮小のアニメーションは追加しない。
- `prefers-reduced-motion: reduce` で全アニメーションを止める（`styles.css` 末尾で一括処理済み）。
- キーボードフォーカスは共通のアクセントリング（`:focus-visible`）。上部バー内のみ例外で無効。
- クリックできるものは hover で必ず反応を返す（背景 `--hover` など）。逆に、**hover で反応するものはクリックできなければならない**。
- ドラッグ操作（パレット・リサイズ）は Pointer Events + `setPointerCapture`、要素に `touch-action: none`。
- ユーザーが動かした位置・開いた状態・幅は localStorage に記憶し、次回も同じ場所に出す。

## 8. 変更時のチェックリスト

- [ ] 色・角丸・文字サイズ・影はすべてトークン参照か（HEX / px 直書きを増やしていないか）
- [ ] 余白は §4 の段階（gap 8px 既定、padding は横 > 縦）に乗っているか。新しい端数を作っていないか
- [ ] ボタンは 5 系統のどれかに乗っているか。primary を増やしすぎていないか（1 画面 1 つ）
- [ ] ライト/ダーク両テーマで確認したか（基準はダーク）
- [ ] 上下バー内で `--bar-*` 以外のトークンを使っていないか
- [ ] スクロール位置・ペイン開閉に関係なく操作と結果が見えるか（sticky / パレット / パネルの配置）
- [ ] フォーカスリング・disabled・hover の状態があるか
- [ ] このスタイルガイドと矛盾する場合、先に本ファイルを更新したか
